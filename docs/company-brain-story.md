# Draft · A company brain that shows its work

> **Unpublished draft.** This is a local prototype story, not a claim of a hosted deployment, real corporate data, external-event eligibility, or a published blog post.

A question like “Why was Analytics Migration delayed?” sounds simple until the answer lives in four places: a ticket, a chat message, a meeting record, and a design document. A useful company brain should connect those records, show which relationship supports each claim, and admit when the graph does not know.

ContextMind's **NovaPay** workspace is deliberately fictional. It stores people, teams, systems, projects, tickets, messages, meetings, documents, and decisions as typed nodes and relationships in a local FalkorDB graph. The decision provenance proof executes a fixed, read-only, parameterized Cypher query: a decision's `BASED_ON` evidence and `IMPACTS` project. Opening a source card reveals the underlying record, rather than asking viewers to trust a polished sentence.

The agent is not an LLM pretending to reason. It resolves named entities, routes supported question forms to bounded tools, and records those calls and their result counts. Ownership questions follow `OWNS` and `LEADS`; impact questions traverse dependencies. A shortest-path question runs an application-side breadth-first search over FalkorDB-backed adjacency reads: Alice Johnson `WORKED_ON` API Gateway, which `DEPENDS_ON` Database Cluster. The search allows up to four hops and 70 visited nodes and excludes saved-answer links that could make misleading shortcuts. This is **not** a native FalkorDB algorithm-library invocation or an autonomous planner. Unsupported questions abstain.

Memory and freshness have to be observable. Saved investigations retain their answer, selected tool calls, and evidence paths across reloads. On an isolated test graph, a token-protected operator can insert a normalized fictional blocker, ask again, resolve it, and ask once more. The latest answer reads the changed graph; earlier snapshots remain historical rather than being silently rewritten. This is a manual ingest demonstration, not a live Slack/Jira synchronization or transactional multi-record pipeline. An ownership path is not a real-time on-call roster.

The separate **public FalkorDB** workspace contains a bounded snapshot of public GitHub artifacts, with URLs, capture time, and integrity metadata. A second fixed native Cypher traversal connects the organization to its Python client and releases. Contributor activity can be cited as activity; it cannot establish a maintainer assignment or private rationale. JSON preview mode labels Cypher as **not executed**.
